# Campus Maintenance Constitution

## Core Principles

### I. Code Quality

All code is TypeScript with `strict` checks. `any` is forbidden unless unavoidable and justified in a comment.
Every change passes ESLint and Prettier (enforced locally by Husky + lint-staged and remotely by CI).
Small, readable functions; names follow the domain language of `specs/campus-maintenance.md`.

### II. Tests for Every Service (NON-NEGOTIABLE)

Every NestJS service method has unit tests covering the happy path and at least one failure path.
Every endpoint has an HTTP-level test that runs through the real global `ValidationPipe`.
A pull request that changes behaviour without changing tests is not mergeable.

### III. MVC Separation

- Controllers handle HTTP concerns only (routing, params, status codes, Swagger decorators).
- Services own business rules and all database access.
- Mongoose schemas define persistence; DTOs define and validate API input.
- The Next.js frontend talks to the API over HTTP only and never touches MongoDB.

### IV. No Secrets in Code

Connection strings, passwords, tokens and API keys live only in untracked `.env` files.
`.env` is git-ignored and protected from AI edits by a Claude Code hook. `.env.example` documents keys with placeholders only.
If a secret is ever pushed, it is rotated immediately.

### V. Spec-Bounded Scope

Only MVP features in `specs/campus-maintenance.md` are built. Anything listed under "Out of scope" needs explicit team approval first.

## Technology Constraints

- Backend: NestJS 11 + Mongoose, port 3001, Swagger at `/api`, OpenAPI JSON at `/api-json`.
- Frontend: Next.js App Router + Tailwind CSS + shadcn/ui on port 3000.
- Database: MongoDB Atlas.
- Shared contract: `apps/web/lib/api-types.ts` generated by `openapi-typescript`; refreshed after every API change.

## Development Workflow

Plan → implement small steps → verify (tests, lint, Playwright) → read the diff → log AI usage in `docs/ai-log.md` → PR using the template → review → green CI (`api`, `web`) → merge.
`main` is protected: no direct pushes, no force pushes.

## Governance

This constitution supersedes ad-hoc practices. Amendments are made by pull request, reviewed by the team, and bump the version (MAJOR for removed/redefined principles, MINOR for additions, PATCH for wording).
Reviewers check every PR against these principles.
